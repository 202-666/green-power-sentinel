## 二、检测算法说明

### 2.1 阈值检测 (threshold_detector.py)

**输入**：参数当前值 + thresholds.yaml 配置
**输出**：超限命中列表 `[{param, level, value, threshold, exceed_ratio}]`

**等级映射**：
- `danger_high/danger_low` → danger (score=1.0)
- `standard_limit` → limit (score=0.85)
- `warning_threshold` → warning (score=0.45)

**特点**：逐行检测（向量化空间有限，因 thresholds 配置结构复杂），耗时 ~1.8s/43200 行

### 2.2 趋势检测 (trend_detector.py)

**算法**：滚动均值差分近似 OLS 斜率

```python
# 原理：对线性趋势 y=a+bx，OLS slope = b
# 近似：slope ≈ (mean(后半窗口) - mean(前半窗口)) / (窗口/2)
# 对线性数据两者等价，对噪声数据均值差分更稳健，且为 O(n) 向量化
half_w = max(w // 2, 1)
second_half = s.rolling(half_w, min_periods=half_w).mean()
first_half = second_half.shift(half_w)
slope_series = (second_half - first_half) / half_w
```

**优化成果**：31s → 0.26s（119× 加速）

**窗口等级映射**：
- 10min → yellow（短窗口噪声大，仅辅助）
- 30min → orange（主趋势检测器）
- 60min → red（最可靠，几乎零误报）

**平滑窗口**：默认 15（炉膛温度 σ≈23 时，可将 10min 斜率 std 从 0.78 降到 0.20）

### 2.3 波动率检测 (volatility_detector.py)

**算法**：当前窗口 std / 基线窗口 std 的比值

```python
current_std = series.rolling(current_window).std()
baseline_std = series.rolling(baseline_window).std()
ratio = current_std / baseline_std
```

**等级映射**：
- ratio ≥ 3.0 → red
- ratio ≥ 2.0 → orange
- ratio ≥ 1.5 → yellow

**基线窗口优化**：1440min → 480min（匹配班组交接周期 8h），耗时 21s → 10s

### 2.4 关联检测 (correlation_detector.py)

**算法**：规则引擎，每条规则含 N 个条件，按 logic 字段组合

**逻辑门**：
- `AND`：所有条件满足才 matched
- `MAJORITY`：`matched * 2 >= total`（含半数，4 条件需 2 匹配）
- `OR`：任一条件满足即 matched

**向量化实现**：NumPy 布尔掩码批量计算所有时间点 × 所有条件

```python
# 对每条规则，预计算所有条件的布尔矩阵 (n_time × n_conditions)
cond_matrix = np.zeros((n_time, n_conditions), dtype=bool)
for j, cond in enumerate(conditions):
    cond_matrix[:, j] = evaluate_condition_vectorized(df, cond, trend_results, vol_results)
matched_count = cond_matrix.sum(axis=1)
if logic == "MAJORITY":
    matched = matched_count * 2 >= n_conditions
elif logic == "AND":
    matched = matched_count == n_conditions
```

**优化成果**：30s → 0.17s（176× 加速）

### 2.5 综合评分 (ensemble_scorer.py)

**评分流程**：

1. **预提取**：各模块分数 → NumPy 数组（th_scores, tr_scores, vol_scores, corr_scores）
2. **加权求和**：`score = Σ(weight_i × module_score_i) / Σ(weight_i)`
3. **等级映射**：score ≥ red/orange/yellow 阈值
4. **allow_single_module_alert**（可选）：强单模块信号（≥0.8）单独达 yellow
5. **persistence_filter**（关键）：过滤瞬时抖动
   - consecutive 模式：连续 N 个 yellow+ 才确认
   - sliding 模式：W 窗口内至少 K 个 yellow+ 才确认
6. **persistence_backfill**（关键创新）：确认后向回填弱信号点
7. **置信度**：`0.2 + active_modules × 0.18 + score × 0.4`

**权重配置**（W8 最终）：
```yaml
weights:
  threshold: 0.2       # 阈值检测（中后期检出，可靠性高）
  trend: 0.3           # 趋势检测（早期检出，权重适中）
  volatility: 0.2      # 波动率检测（辅助）
  correlation: 0.3     # 关联检测（规则引擎，最可靠）
```

**风险等级阈值**（W8 优化，平衡误报与检出率）：
```yaml
risk_levels:
  red: 0.75            # 高危报警
  orange: 0.65         # 中等报警
  yellow: 0.55         # 低危预警（需多模块协同触发）
```

### 4.2 normal_baseline 集成说明

**模块**：[core/normal_baseline.py](file:///e:/CYZ/飞书ai先锋人才大赛/green-power-sentinel/core/normal_baseline.py)

**算法**：
```python
# 动态斜率阈值 = k * std / sqrt(window) * window_factor
# std: 参数正常波动幅度（基线窗口中位数）
# sqrt(window): 归一化窗口长度
# k: 灵敏度系数（3.0 = 3σ 显著性）
# window_factor: 短窗口放宽（10min=1.5, 30min=1.0, 60min=0.8）
```

**集成方式**（pipeline.py）：
```python
if detection_cfg.get("trend_dynamic_threshold", False):
    normal_mask = df["data_quality_flag"] != "故障注入"
    baseline_df = df[normal_mask]
    baseline = compute_baseline(baseline_df, param_columns, window_size=480)
    trend_thresholds = baseline["slope_thresholds"]
trend_multi = detect_trend_multi_params(df, param_columns, thresholds=trend_thresholds)
```

**当前状态**：默认关闭（`trend_dynamic_threshold: false`），benchmark 使用固定阈值。开启后 furnace_temperature 10min 阈值 29.7（固定 6.0），偏松，需按参数标定 k 值。

### 4.3 增量检测接口

**方法**：`SentinelPipeline.run_incremental_detection(data_source, device_id, last_row_idx)`

**策略**：
1. 读取完整数据（实时场景可改为追加读取）
2. 窗口预热：取 last_row_idx 前 max(trend_windows, vol_baseline_window)+10 行作为上下文
3. 对 [上下文 + 新增行] 执行全检测
4. 仅提取新增行对应的评分与异常
5. 返回 `{new_rows, new_anomalies, last_row_idx, context_rows}`

**限制说明**：
- 趋势/波动率检测依赖滚动窗口，新增行需包含前序上下文
- 增量结果与全量结果在边界点可能存在微小差异（窗口预热）
- 首次调用（last_row_idx=0）等价于全量检测
- 阈值 / 趋势 / 波动率 / 关联 / 综合评分五段各自 try-except 隔离（H2），
  任一模块异常仅跳过该模块，不中断增量流程

### 4.4 JSON compact 输出

**方法**：`SentinelPipeline.save_detection_results(out_path, compact=True)`

| 模式 | 内容 | 大小（43200 行） |
|---|---|---|
| compact=False | 全量 scores + time_series + anomalies | 29 MB |
| compact=True | 仅 anomalies + perf | 83 KB |

**压缩比 0.3%**，适用于传输/展示场景。

## 六、改进建议（后续优化方向）

### 6.1 性能优化

1. **综合评分预提取循环**（W8 已优化）
   - 现状：改用 enumerate + 生成器表达式优化数据访问模式，减少中间变量创建
   - 效果：预提取循环性能显著提升，减少内存分配开销

2. **Numba/Cython 加速**
   - 适用：预提取循环、backfill 反向 rolling
   - 预期：41s 总耗时 → < 5s

3. **多进程并行**
   - 适用：13 个参数的趋势/波动率检测可并行
   - 预期：10s → 2s（6 核并行）

### 6.2 算法演进

1. **动态基线阈值标定**
   - 现状：`trend_dynamic_threshold` 已实现，但 k=3.0 全局统一偏松
   - 建议：按参数标定 k 值（furnace_temperature k=2.0，steam_pressure k=4.0）

2. **ensemble 权重动态调整**
   - 现状：`dynamic_weight: true` 仅为配置占位
   - 建议：基于规则历史匹配率动态调整（R2 当前 18.9%，可降低其权重）

3. **ML 异常检测补充**
   - 现状：全规则驱动
   - 建议：补充 Isolation Forest / Autoencoder 作为弱监督信号，与规则引擎融合

4. **因果推理**
   - 现状：关联检测仅做时序同步
   - 建议：引入 Granger 因果检验区分"相关"与"因果"

### 6.3 工程化

1. **流式数据源对接**
   - 现状：`run_incremental_detection` 已实现，但仅支持 CSV
   - 建议：对接 Kafka/MQTT 实时流

2. **多设备联邦基线**
   - 现状：基线单设备计算
   - 建议：扩展为同型号设备群联邦基线

3. **模型版本管理**
   - 现状：规则与阈值硬编码在 yaml
   - 建议：引入 MLflow 管理规则版本与 A/B 测试
